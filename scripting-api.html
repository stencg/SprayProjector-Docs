Scripting API

Guide home / Scripting API

This page is for developers connecting tools and UI. For Inspector setup, start with Getting started.

Runtime types use Assets.SprayProjector.Scripts. Binary packages include public API documentation in Runtime/Plugins/SprayProjector.Scripts.xml.

Drive a projector

Call one appropriate action each frame according to your input state. The following are separate usage examples, not a sequence to execute together.


// While aiming:
projector.PreviewProjection(Color.white);

// While painting: alpha supplies raw pressure.
projector.Paint(new Color(1f, 0.1f, 0.05f, pressure));

// Or supply finish properties as RGB: metalness, smoothness, wetness.
projector.Paint(color, new Color(metalness, smoothness, wetness));

// When painting ends:
projector.Stop();

Paint() without arguments uses the projector's component color and finish values. Input alpha below 0.01 calls Stop(). Stop resets stroke interpolation, selection, and preview state controlled by that projector.

Initialization and receiver preparation are asynchronous across frames. Calls made before readiness do not necessarily produce a mark; keep driving the tool while input is active.

Emit drips

Call during painting after the scene's drip components have initialized:


dripEmitter.DetectDrip(color, new Color(metalness, smoothness, wetness));

The overloads without explicit finish data use the emitter's component values. Detection requires a registered drip surface, Allow Drips, and a ready receiver; see Drips.

Prepare and load a receiver

GetReadyToPaint() is a polling entry point: it prepares textures and starts loading when needed, returning false until the receiver can accept paint. Call again on later frames; do not busy-wait in the same frame.

LoadDataToPaintTask() expects existing paint render textures. Calling it on a cold receiver does not allocate those textures.


// Reload an already prepared receiver when it is not busy.
if (receiver.GetReadyToPaint())
{
    await receiver.LoadDataToPaintTask();
}

LoadPreviewDataTask() loads and applies the saved low-resolution preview and returns a success flag. SetPreview() only reapplies already-existing preview textures; it does not load or generate them.

Save and manage the scene

APIBehavior
ReceiversManager.Instance.SaveAll()Starts the manager's save queue; returns without starting a new queue if the manager is busy
ReceiversManager.Instance.ReloadDirtyReceivers()Reloads dirty receivers that are not busy
ReceiversManager.Instance.PreviewAll()Switches receivers to saved previews and releases full textures
receiver.SaveChain(preview: true)Coroutine for saving one receiver and updating its preview
receiver.ExportToPNG(directory)Async-void color-image export; requires an existing paint texture, GPU readback, and writable output directory

Call manager APIs only when Instance exists. Use its saving events and progress fields for UI feedback. A receiver's SaveChain skips saving when busy, saving is disallowed, GPU readback is unsupported, or no changes are marked.

From a MonoBehaviour coroutine, a single-receiver save can be driven with:


yield return StartCoroutine(receiver.SaveChain(preview: true));

Clear deliberately

  • ClearReceivers(false) releases full textures and retains saved files and preview textures.
  • ClearReceivers(true) also resets receivers and deletes their saved files.
  • receiver.ClearStorage() deletes saved files without itself releasing live textures.
  • receiver.DestroyTextures(true) releases live and preview textures without deleting files.

Read Saving and loading for IDs, layout compatibility, storage location, and save precision. Internal jobs and Editor implementation types are outside this API guide.
