Saving and loading

Guide home / Saving and loading

Goal: keep painted work between sessions and understand which clear operations remove it.

Prepare each receiver

  1. Enable Allow Saving.
  2. In the PaintReceiver component menu, choose Generate New ID if its ID is empty.
  3. Give every independently saved receiver a unique ID. Duplicating a configured object also duplicates its ID, so generate a new one for the copy.
  4. You can open Window/UI Toolkit/Paint Tools. It allows you to generate ID and UV World Scale by one click for all objects on your scene.

Keep IDs stable after saving. Empty IDs or invalid filename characters disable saving. Receivers with the same ID use the same save filenames.

Saved files go to Unity's Application.persistentDataPath, not the project asset folder. Saving requires asynchronous GPU readback support on hardware; the receiver disables saving if the device does not support it.

Save and verify

Use one ReceiversManager for scene-wide operations. In the demo:

  1. Paint a recognizable mark.
  2. Choose Save and wait for saving to finish.
  3. Moving Main Camera far away from Receivers also force saving per Distance Culling settings in the manager.
  4. Add another mark without saving.
  5. Choose Reload to reload saved data for receivers with unsaved changes.

Reload is connected to ReloadDirtyReceivers(): it does not force every receiver in the scene to reload. A developer can connect custom UI using the scripting reference.

Automatic periodic saving is off by default. The manager's Save Queue Interval enables it only at values of 10 seconds or more. Do not assume stopping Play Mode saves your work.

Understand the two previews

Preview typePurpose
Projector aiming previewShows the mark before you paint; controlled by PreviewProjection
Saved-paint previewDisplays a lighter copy of previously saved paint without keeping full paint render textures allocated

Saved previews use half the width and height of the full texture, with four bits per color channel. They can look softer or show more banding. Returning to painting prepares the full textures and loads saved data.

The demo's Preview button calls PreviewAll(), which can save dirty receivers and release their full render textures. It is not an aiming-preview toggle. Save-enabled receivers are required for this workflow to preserve unsaved work.

The receiver's Allow Loading Preview On Start field is currently declared but not read by the implementation. Do not rely on that checkbox alone; use the manager or an explicit preview-load call.

Clear without surprises

OperationCurrent texturesSaved files
Projector ClearTarget()Releases paint and preview textures on the receiver hit within 2 mKept
Manager ClearReceivers(false)Releases full paint textures; retains preview texturesKept
Manager ClearReceivers(true)Releases textures and resets receiversDeleted
Receiver ClearStorage()Does not itself release current texturesDeleted

The demo's Clear button calls ClearReceivers(true), deleting saved paint for registered receivers. Back up files before using it if you want to keep the artwork.

Releasing textures discards unsaved texture contents. If saved files remain, painting or loading can bring their contents back.

Export an image

ExportToPNG(directory) exports the receiver's current paint-color texture, using the seam-extended texture when Fix Seams is enabled. Prepare the full paint textures first and provide an existing, writable output directory.

PNG export requires asynchronous GPU readback. It does not export the complete material, mesh, or additional paint data, and is not the package's reloadable save format.

Color HQ is a runtime precision setting: the full save path converts paint to 8-bit-per-channel data, so it does not preserve the full precision of the 16-bit runtime color texture.
