Demo dependencies

  • Unity UI (uGUI): required for the Spray Demo UI.
  • Input System: recommended for the demo, but not required by the core package.
  • Legacy input: supported by a separate demo backend when Input System is not enabled.

Follow Sample exploration to configure the EventSystem for your selected input backend.

Rendering and device checks

Use a URP project with the supplied receiver shaders. The code includes URP compatibility handling; it does not establish support for Built-in or HDRP materials.

Saving and PNG export require asynchronous GPU readback. Receiver initialization also requires the supplied compute shader references. Check these features on the intended device.

Before delivery, test painting, saving, shader variants, texture memory, and any XR interaction in a target Player or headset. A successful compilation alone does not verify those behaviors.

Demo setup requirements

The Spray Demo requires Unity UI (uGUI) and the built-in Animation, Audio, and Particle System modules.

For Input System input, install the Input System package and set Project Settings > Player > Other Settings > Active Input Handling to Input System Package (New) or Both. Restart Unity if prompted. For legacy-only input, choose Input Manager (Old) and retain the Horizontal, Vertical, Submit, Cancel, and Mouse ScrollWheel entries used by the UI and demo controls. See Sample exploration for EventSystem setup.

Drip requirements

  • Use stationary receivers for drips; moving receivers are not supported by the drip setup.
  • Use a non-convex MeshCollider on each receiving renderer's GameObject. This collider setup is for non-physics objects under Unity Physics rules.
  • Enable mesh Read/Write where needed so raycasts can provide hit texture coordinates.

See Drips for the complete scene setup.
