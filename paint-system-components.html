The basic painting setup

Component or assetRoleWhat to assign
PaintProjectorThe nozzle or brush that projects paint forwardPaint Settings and a controller that calls Paint
PaintSettingsReusable paint stylePaint shader, profile texture, and visual controls
PaintReceiverThe surface that owns accumulated paint texturesReceiver Settings, renderers, and an ID if saving
ReceiverSettingsShared texture resolution and processing resourcesPaint processing shader, seam shader, compute shaders, and noise

The visible receiver material is separate from Receiver Settings. It uses a Paint Receiver shader to display the textures.

A projector does not paint automatically. A receiver missing Receiver Settings logs an error and disables itself; assign the asset and re-enable it. Warmup and loading may require more than one frame before painting can begin.

Optional scene features

ComponentUse it forPlacement
ReceiversManagerScene-wide saving, preview loading, clearing, and distance-based texture managementOne persistent manager across loaded scenes
PaintDripSystemSimulating running paintOne persistent instance
PaintDripRendererDrawing simulated trails into receiversOne persistent instance
PaintDripEmitterCreating drips when paint builds upOn each nozzle that should emit drips
PaintReceiverProxyConnecting a separate collider to a receiver for paintingOn the collider object; assign Receiver
DisablePaintOcclusionExcluding a renderer from projector occlusionOn the renderer's GameObject

Basic painting can work without ReceiversManager. The manager is needed for the supplied scene-wide orchestration, not for every individual stroke.

For developers

The runtime types above use the Assets.SprayProjector.Scripts namespace. Sample controllers are separate from the runtime package API.

See Scripting API for calls and prerequisites.
